## 實作範圍

1. 合併前三步為「文稿」，後續「試聽與製作」保留既有功能。匯入後直接顯示同一可編輯全文。
2. PDF 原頁與 TXT 原文位於左側，可收合。AI 前後左右布局、頁碼、欄寬與編輯狀態保持一致。主視窗最大化，縮小時主要操作仍可見。
3. 把 PDF 對照、AI 全文候選、搜尋、版本、文稿設定、來源處理及來源異常整合進主視窗；取消正常路徑的多個工作視窗。工具面板收合與切換不丟失輸入。
4. 一次啟動目前文件全文 AI 校對；沿用背景切批、檢核、進度、取消、重試與續作。候選在同一全文編輯器可修改，不要求逐段採用。忙碌時停用衝突操作。
5. 新增單一「儲存為朗讀稿」操作，保存畫面最新全文並建立對應快照。提交須一致，重複保存相同內容不產生重複版本。不可沿用先保存、再失敗確認卻顯示成功的行為。
6. 暫存草稿與正式朗讀版本分離。重開專案恢復草稿／未完成候選。版本還原先保留現稿；來源重辨預覽後才套用。全文人工修改造成頁碼映射失效時如實顯示。
7. 部分 AI 成功先允許續作；若選保留未完成處原文才可保存混合全文。取消與晚到結果不得破壞人工文字。來源異常仍須明確處理。
8. 文稿設定的模型允許手動輸入，選項持久保存；金鑰不進專案。TXT 編碼與 PDF 頁面／OCR 欄位依來源切換。保留既有旋轉、局部重辨、失敗頁重試、匯出及復原能力，移至適當工具入口。

## 驗收與證據

- 匯入 PDF／TXT → 檢查主工作區 → 確認全文可編輯且沒有新增工作視窗。
- 展開原頁 → 啟動全文 AI → 等待完成 → 確認原頁狀態保留、全文差異可編輯且不需逐段採用。
- 修改候選 → 儲存為朗讀稿 → 讀取快照 → 確認與畫面全文一致，無額外確認頁／彈窗。
- 模擬部分失敗、取消、過期結果及保存失敗 → 確認原稿和人工修改保留，失敗不顯示可朗讀。
- 暫存後重開 → 檢查草稿及候選 → 確認可續作且未誤認為已確認朗讀稿。
- 開啟搜尋、版本、設定及來源工具 → 操作後收合 → 確認輸入、文稿位置與底部操作保留。
- 選版本 → 查看差異 → 還原到編輯稿 → 確認現稿已備份且需再次儲存為朗讀稿。
- 重新擷取 → 預覽差異 → 套用 → 確認人工文稿未被靜默覆寫。
- 重開舊專案 → 使用舊版本／候選及既有語音 → 確認相容與失效規則正確。
- 在最大化及還原視窗執行原生 Tk 視覺驗收 → 確認無裁切、重疊、整頁巢狀捲動與水平捲動。

測試以實際使用行為及持久化結果為主。更新依賴舊四步驟／視窗的測試，同時保留版本、來源異常、重試與資料保護測試。AI 流程可用可控回應驗證；若未做真實雲端品質驗證須明列，不以模擬結果宣稱已驗證。
