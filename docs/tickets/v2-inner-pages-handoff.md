## 遷移順序與責任

### 1. 主 agent 先建立內頁共用契約

盤點每一個工具入口及其返回路徑。分開記錄兩份對照：

- 功能：能力 → 現有入口 → 遷移後入口 → 狀態／資料持有者 → 驗證證據。
- 布局：標頭／工具／內容／狀態／操作的分組與空間 → 原生父容器及共用介面 → 尺寸與捲動驗收。

沿用 `DesktopShell`、`WorkspaceFrame`、`ActionBar`、`ActionSpec`、`PagePresentation`，先檢查它們是否足以支援內頁。必要時由主 agent 擴充共同的內頁宿主／區域操作介面：固定父容器、頁面身分、標題、返回、適用操作、狀態與忙碌狀態。區域提交與全域下一步的語意須清楚，避免重複保存或返回入口。

頁面提供呈現資料及命令，框架管理共用布局；內容模組管理自己的內容。相容別名與 `install_legacy_handles()` 是過渡入口，逐步減少頁面交叉修改共用控制項。拆檔、包一層 Frame 或改用樣式名稱，均不足以宣稱模組化完成。也不強迫每個小功能各建一檔；以責任及狀態邊界決定。

既有 UI 作為基線。純模組抽取保留布局；若要調整布局，依 AGENTS.md 第12點，先提供正常、縮小、工具展開圖及對照，取得確認後才實作。既有通用示意圖不是其他內頁完整布局的核准證據。

### 2. 文稿工具內頁先遷移

| 內頁／能力 | 現有來源入口 | 必保留的行為 |
| --- | --- | --- |
| 版本紀錄、歷史候選、預覽／還原 | `manuscript_desktop.py` 的 `build_version_tools`、`show_versions` 等 | 唯讀預覽；還原前備份；版本隔離；返回保留現稿、選取、游標、捲動 |
| AI 設定、連線設定／測試 | 同檔 `build_manuscript_settings`、`gemini_settings` 等 | 自訂模型、文字／字級偏好；安全憑證仍留本機；錯誤不丟輸入；不恢復已移除的傳送同意框 |
| 來源處理、匯入／重載、異常 | `manuscript_source.py:SourceTools` 及文稿入口 | PDF／TXT 適用欄位；編碼；旋轉、框選、重辨、重試；先預覽再採用；人工稿與原來源保護 |
| 換行整理預覽 | `manuscript_cleanup.py:LineBreakPreview` | 有變更才提交；先備份；保存失敗保留；過期拒絕；一次復原；未完成 AI 結果限制 |
| 搜尋／取代、其餘編輯工具 | 文稿搜尋列與選單回呼 | 操作同一全文編輯器；復原、搜尋選取與上下文保留；匯出使用畫面全文 |

先完成一個代表性內頁，例如版本紀錄，驗證共用宿主／操作與返回契約，再接其他工具。檢查整張畫面，包含既有文稿、列表、導覽及底列。工具內容可因任務不同採 Text、表單或並列原頁，保持明確捲動擁有者。
