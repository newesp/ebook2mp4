## 保存配置

| 用途 | 位置／規則 |
| --- | --- |
| v1 原始碼封存 | `archives/v1/source/`，包含本次命名時點執行及重建所需的完整來源、測試、建置設定與必要資源 |
| v1 可執行成品封存 | `archives/v1/ebook2mp4/`，完整複製現有 `dist/ebook2mp4`，包含 `_internal` 等相依檔，不只複製 EXE |
| v1 封存清單 | `archives/v1/manifest.json`，記錄時間、來源識別、檔案清單與 SHA-256、依賴／工具版本、啟動方式與已知限制 |
| v1 最終驗證證據 | `docs/verification/v1-baseline/`，保留原始碼／成品一致性、原生操作、退出及清理記錄 |
| v2 開發來源 | 現有專案根目錄，以封存的 v1 程式碼為起點繼續開發，不修改 `archives/v1` |
| v2 正式建置 | 仍固定為 `dist/ebook2mp4`；只在 v1 完整封存及啟動驗證通過後才覆寫 |

`archives/v1` 是保留既有版本的封存副本，不是新的建置輸出位置，不對此目錄執行 PyInstaller 建置。封存完成後，不覆寫、不清理為測試暫存；日後 v1 修補須另建版本，不直接改封存。

## 執行步驟

1. 盤點命名時點的來源與正式成品。必要的未提交修改、未追蹤檔案及被忽略的執行資源都須檢查；不能把目前 Git HEAD 直接視為完整 v1。
2. 列出封存檔案。排除書稿、私人專案、API 金鑰、使用者設定、快取及測試／建置暫存；保留重建需要的資源及依賴描述，不將封存目錄遞迴複製到自身。缺少必要外部工具或模型時記錄取得方式及版本。
3. 確認正式程式已正常關閉、檔案未占用。複製完整來源與成品至封存位置；既有目標若非空先核對，不能直接覆寫。使用者程序如需強制結束，須先取得授權。
4. 產生逐檔雜湊與 manifest。核對 EXE 內程式模組與目前來源是否一致；不一致須查明並記錄，不能將兩份不同程式宣稱為相同 v1 基準。任何補建仍只輸出 `dist/ebook2mp4`，且先保留既有成品。
5. 從封存來源以 `python -m ebook2mp4` 啟動。從封存完整成品啟動 `ebook2mp4.exe`。各自使用隔離設定及合成書籍專案，確認不靠 v2 的目錄或系統 Python 才能執行封裝版。
6. 記錄來源識別。可使用包含必要檔案的本機 Git 提交及不可移動的標籤輔助還原；原始碼副本與雜湊清單仍須保留。不把金鑰、私人書稿、完整封裝二進位或暫存一併加入 Git，不在此票要求推送遠端。
7. 核對 v2 開發來源與 v1 基準。將後續程式變更歸入 v2；完成後才解除 v2 開發與建置前置條件。

## 設定與資料隔離

v1／v2 使用各自的測試專案副本，不同時改寫同一本書。盤點最近專案記錄、語音設定、服務設定、金鑰、模型及快取；不能只更換 EXE 名稱便認定已隔離。

現有 `EBOOK2MP4_APP_HOME` 可隔離最近專案記錄，`EBOOK2MP4_VOICE_HOME` 有既有語音用途；其他設定來源須逐項核對，這兩個變數不代表所有本機設定都已隔離。v2 若需新增版本專屬設定位置，另於 v2 實作並驗證，不修改 v1 封存。金鑰不放入封存或測試證據。

## 驗收與完成條件

1. 檢查來源清單 → 確認必要未提交／未追蹤檔案及建置資源已保存。
2. 啟動 v1 封存來源 → 開啟合成專案 → 編輯並保存 → 正常退出。確認來源可獨立執行。
3. 啟動 v1 封存 EXE → 開啟同等內容的另一隔離專案 → 切換主要頁面 → 保存並重開。確認封存成品可獨立執行且不改使用者設定。
4. 用受控服務完成短篇音訊及真實本機影片輸出 → 播放與另存 → 確認成品有效。記錄受控／真實工具及未驗證服務；不為封存測試新增計費請求。
5. 關閉 v1 → 核對程序與占用 → 確認本次測試資源已釋放。
6. v2 每次正式交付後 → 重算 v1 封存雜湊並重新啟動 v1 → 確認 v1 未被改寫；再獨立啟動 v2 → 確認兩版皆可操作與正常退出。

前五項及清單／雜湊證據完成後，才可標記 v1 封存完成並開始 v2 產品程式開發。第六項為 v2 持續交付的回歸要求。清理僅限本次自建測試資料、暫存及程序，保留 v1 封存及最終證據。
