# 全專案訊息浮層評估與套用清單

日期：2026-10-27。範圍：正式 Tkinter 桌面介面。本次只評估，未修改程式或封裝成品。

## 建議

採用共用、非阻斷的通知浮層（toast），用於操作結果；不要把頻繁的成功回饋改成需要按確定的 message box。

使用者截圖顯示：Gemini「採用本段」位於右下，結果文字位於左下，視線必須跨越整個寬視窗。這是回饋位置與視覺層級問題，僅更換文案仍無法解決。現有程式將狀態 Label 與操作按鈕分成兩列，沒有建立兩者的視覺關聯。

依使用者選定方向，所有通知浮層統一固定在**目前操作視窗的上方中央**。主工作台、Gemini、PDF/OCR、語音及設定視窗使用相同定位規則，讓使用者在固定位置查看回饋。以所屬視窗的內容區為基準水平置中，距內容區頂端保留一致邊距；不依觸發按鈕、滑鼠或面板位置移動。採用既有綠色、紙白、微軟正黑體及方正原生介面，不引入另一套裝飾樣式。

Gemini 成功提示示例：「已儲存並採用第 3 段」。如何繼續編輯的說明留在介面說明或訊息詳細內容，不塞進短暫提示。

## 共用互動規格

| 項目 | 建議 |
|---|---|
| 統一位置 | 所屬視窗內容區上方中央，頂端邊距建議 16 邏輯像素；所有通知嚴重程度使用同一錨點，縮放或移動視窗時保持置中 |
| 成功訊息 | 顯示約 3 秒，再以約 250ms ease-out 淡出；右上提供 × 關閉 |
| 一般提醒 | 短訊息可同樣自動關閉；較長內容延長閱讀時間，或改常駐說明 |
| 錯誤／需處理警告 | 不自動消失；保留原處錯誤與修正入口，浮層僅作醒目補充 |
| 滑鼠／鍵盤 | 懸停或鍵盤焦點進入時暫停倒數；不搶編輯焦點、不 grab、不要求按確定 |
| 關閉 | × 只關閉提示，不取消工作、不變更採用決定、不解除來源阻擋 |
| 快速連續操作 | 每個視窗同時一則，新結果替換舊結果並重設計時；所有結果仍可由訊息記錄查閱 |
| 內容 | 用「成功／提醒／失敗」文字及簡單符號搭配色彩；1～2 行短文，不只靠顏色辨識 |
| 尺寸 | 建議寬約 320～400 邏輯像素，隨視窗縮窄；保留邊距、換行，不越出視窗或遮住主要按鈕 |
| 歷史 | 延用主工作台「操作訊息」入口，補上子視窗事件；保留完整訊息、來源視窗與必要的批次／段落識別 |
| 多視窗 | 提示屬於觸發操作的視窗，固定於該視窗上方中央。完成後關閉子視窗的操作，交由仍存在的主視窗在其上方中央顯示結果；不固定於整個螢幕 |
| 動畫降級 | 無法可靠淡出或使用者停用動畫時，倒數結束直接關閉；不影響操作完成 |

關閉警告浮層後，未存稿、舊版本候選、未完成頁等常駐狀態仍須存在；提示顯示與業務狀態解除是兩件事。

## 適合套用的位置

「新增回饋」表示目前只有畫面更新或通用載入訊息，建議在原有成功分支補上明確的結果。表內為預定套用範圍，尚未實作。

| 區域／操作 | 建議呈現 | 現有位置／注意事項 |
|---|---|---|
| Gemini 採用本段、採用全部待確認段 | 成功浮層，3 秒 | `gemini_desktop.py: ReviewDialog.decide / perform`；顯示實際段次或處理數 |
| Gemini 拒絕本段、撤回全部採用 | 成功浮層，3 秒 | `ReviewDialog.decide / undo / perform`；撤回使用獨立文案，不能只顯示通用「已儲存決定」 |
| Gemini 手動保存候選修改 | 成功浮層，3 秒 | `ReviewDialog.save_candidate_edits`；明示「候選已儲存，尚未套用」 |
| Gemini 校對完成且候選保存成功 | 完成浮層，3 秒 | `ReviewDialog.poll`；只有完整成功用成功提示；部分成功保留進度及失敗範圍 |
| Gemini 設定保存、連線測試成功 | 成功浮層，3 秒 | `SettingsDialog.save / poll`；「保存並測試」合併成最終測試結果，避免連跳兩則 |
| 主工作台保存校對稿 | 成功浮層，3 秒 | `desktop.py: Workbench.save`；僅使用者主動保存需要提示，內部前置保存合併到最終操作結果 |
| TXT 匯出 | 成功浮層，3 秒 | `Workbench.export_txt`；短文顯示檔名，完整路徑保留於訊息記錄 |
| 確認朗讀稿 | 成功浮層，3 秒 | `Workbench.confirm_reading`；保留原確認對話框及常駐朗讀狀態 |
| 換行整理套用 | 成功浮層，3 秒，顯示在主視窗 | `Workbench.cleanup_line_breaks.apply`；預覽視窗會關閉，仍保留 Ctrl+Z 一次復原語意 |
| 取代文字 | 成功浮層，3 秒 | `Workbench.replace_all`；保留取代數量、可復原說明；`replace_one` 可補低干擾回饋，避免連續取代過度提示 |
| 搜尋無結果、沒有可復原內容 | 一般提醒浮層，3 秒 | `Workbench.find_next / undo`；不使用成功綠色 |
| 移除 PDF 批次、刪除朗讀稿版本 | 確認後的成功浮層 | `Workbench.remove_pdf / show_versions.delete`；原確認對話框保留；刪除附帶清理失敗時顯示警告，不宣告完全成功 |
| 建立／開啟專案、TXT 匯入／重載 | 新增成功浮層，必要時顯示在主視窗 | `Workbench.create / open / import_txt.commit`；不能對每次 `refresh()` 都彈出「已載入專案」 |
| 批次改名 | 可新增成功浮層 | `Workbench.rename_batch`；說明已儲存新名稱；批次上下移已有即時清單回饋，預設不必逐次彈出 |
| 來源異常已核對／明確略過 | 新增成功浮層 | `Workbench.review_source_issues.decide`、`pdf_desktop.py: PdfDialog.resolve_page`；保留確認及未處理數量 |
| PDF「保留選擇，繼續修正」 | 成功浮層，3 秒 | `PdfDialog.continue_regions`；下一步操作說明維持常駐，不能一同消失 |
| PDF/OCR 辨識完成、修正預覽就緒 | 完成提醒浮層，3 秒 | `PdfDialog.poll`；明示「辨識完成，尚未存成新批次」；部分取消／失敗需另保留頁面狀態 |
| PDF「存成新批次」／直接匯入完成 | 新增成功浮層，顯示在主視窗 | `PdfDialog.accept_candidate / poll`；保存成功後原視窗會關閉 |
| OCR 模型下載完成 | 成功浮層，3 秒 | `PdfDialog.poll` 的 model_job 完成分支；只有真實下載成功才提示；「模型已就緒」查詢不反覆彈出 |
| 語音設定保存 | 成功浮層，3 秒 | `voice_desktop.py: VoiceDialog.save`；試聽前的內部保存不另彈提示 |
| 音色清單更新、試聽完成 | 完成浮層，3 秒 | `VoiceDialog.poll`；播放按鈕及上次成功結果資訊維持常駐 |
| 語音工作取消完成 | 一般提醒浮層 | `VoiceDialog.poll`；等待資源釋放期間維持進度，完成後才顯示「已取消」 |
| 尚無朗讀稿／重載備份可查閱 | 可改為一般提醒 | `Workbench.show_versions` 的空狀態 `showinfo`；可省去一次必須按確定的中斷 |

## 不應直接改成自動消失提示的位置

| 類型 | 具體位置 | 原因 |
|---|---|---|
| 必須決策的確認 | 未存稿離開、來源重載衝突、移除批次、刪除版本、來源警告略過、線上送出、捨棄未保存候選／試聽 | 必須取得明確決定，保留 `askyesno / askyesnocancel` |
| 需持續可見的狀態 | 校對稿已存／未存、朗讀確認、來源異常數、候選待確認／已採用、版本過期 | 浮層消失不代表狀態失效；保持既有統計／阻擋列 |
| 每次編輯產生的提醒 | `ReviewDialog.candidate_modified` | 不逐字彈出「未存修改」；用候選狀態提示 |
| 長時間工作進度 | Gemini 請求完成／失敗／未完成數、OCR 下載量與頁數、試聽生成、取消／釋放中 | 不能三秒後消失；保留既有進度元件 |
| 欄位與操作前置條件 | TXT 編碼預覽、損壞文字確認、PDF 頁次／框選範圍、語音同意勾選及字數限制 | 就近顯示並維持可見，必要時移動焦點；可另外用提醒吸引注意 |
| 重要儲存失敗及衝突 | `Workbench.report`、候選保存失敗、另一視窗更新、磁碟空間／權限錯誤 | 不全面移除現有錯誤對話框；先保留可操作的錯誤與重試／保留修改入口 |
| 使用者主動查閱的詳細資料 | 專案與來源資訊、規則說明、完整路徑／雜湊、版本內容 | 屬閱讀介面，保留可停留、複製的詳細視窗 |
| 即時選擇狀態 | PDF 採用／捨棄選擇、框選提示、音色／語速選擇、批次排序 | 不是完成／保存結果；不能把「將採用」誤報成「已儲存」 |

## 實作切入點與風險

建議在 `ebook2mp4/ui_controls.py` 增加共用通知控制器，由每個頂層視窗傳入 owner、訊息嚴重程度及短文；主工作台的 `MessageLine` 和 `show_messages()` 延用為歷史入口。PDF 的 `_OperationMessage` 仍負責常駐說明及完整錯誤，不把它直接轉成通知發射器。

必須在「使用者操作真正完成」的分支明確觸發，不以「已」字開頭或全域攔截 `Label.configure(text=...)` 來猜測。否則會出現：

- Gemini 採用前先自動保存候選，同一次操作連跳保存／採用兩則。
- 語音試聽前保存設定，先報成功、後報試聽失敗。
- PDF 每 40ms、Gemini 每 60ms、語音每 100ms 的輪詢重複產生通知。
- 子視窗關閉時，提示與計時器一起失效；或全域置頂提示留在其他程式上。

淡出可能需要獨立的原生浮層視窗；這是待驗證的實作方向，不承諾純 Tk 元件可直接做局部透明動畫。實作時須驗證 Windows 視窗層級、DPI、多螢幕及不搶焦點行為。owner 移動／縮放／最小化／關閉時，浮層及 `after` 計時器都要同步處理；從工作執行緒回報結果時，畫面更新仍由 Tk 主執行緒負責。

## 建議順序與驗收

1. 共用浮層、× 關閉、倒數／淡出、完整訊息歷史與資源清理；先套 Gemini 採用／拒絕／撤回／手動保存。
2. 套用主工作台保存／匯出／確認／取代，以及子視窗關閉後交接回饋。
3. 套 PDF/OCR 與語音完成事件，補齊目前只有畫面更新的成功回饋；最後才逐一評估一般錯誤是否減少 modal。

驗收必須覆蓋：各視窗與各類通知均維持內容區上方中央、視窗移動／縮放後仍保持置中且無裁切、3 秒關閉、× 提前關閉、懸停暫停、不搶文字焦點、連續採用不同段落、背景完成、部分成功、保存失敗不得出現成功提示、視窗關閉後無殘留浮層／計時器、最小視窗與不同 DPI、完整訊息可回查。Gemini/PDF 的 740×570、主窗的 1040×640 及較小設定視窗應一起測試；無動畫模式與鍵盤／輔助使用也應驗證。
