# UI 捲動交付門檻

適用所有本專案 UI 設計、靜態 mock、繪圖程式、原生實作及驗收。由根目錄 AGENTS.md 強制連入；新 session 與子 agent 沿用同一入口。專案特殊尺寸仍以相應 ticket 為準。

## 設計／mock 交付

1. 逐頁、逐尺寸、逐展開狀態列出每個可能溢出的區域，以及內容完全容納的區域。記錄 owner、方向、viewport 高度、完整內容高度、是否顯示捲軸、最大 offset。尺寸與內容高度須來自實際布局／文字量測或繪圖程式使用的同一份布局資料，不能事後猜填。
2. 完整容納 → 捲軸隱藏且不留空軌道、offset 為0。實際溢出 → 顯示所屬區域的有效捲軸、offset可到達完整內容末端；滑塊比例依可見範圍計算。原生最小滑塊長度等平台限制須註明，不照搬任意固定滑塊。
3. 捲動擁有者與固定區域在圖中可辨。差異的捲軸只對應差異；固定搜尋、版本選擇、導覽及提交操作不跟著正文捲走。平行區域各自捲動；同軸巢狀需要明確邊界契約，並單獨驗收。
4. 每個區域至少覆蓋短內容、剛好容納、溢出、長內容。展開／收合、改視窗／字級後重新量測。完整容納的設定頁是必要反例，不能只用長文證明需要捲軸。
5. 把上述資料寫入該批 `scroll-contract.json`。先執行 `python -B tools/check_ui_scroll_contract.py <檔案路徑>`，再以原尺寸圖核對。失敗、缺頁、只檢查部分圖，均標為「捲動檢查未通過／未完成」，先修設計再送確認。該檢查只驗幾何契約，不證明視覺或操作可用。

契約格式由檢查程式定義：`coverage_complete`、`regions`；每筆含 `page`、`state`、`owner`、`viewport_height`、`content_height`、`scrollbar_visible`、`max_offset`。可見捲軸另含 `thumb_fraction`（可見比例，不是像素長度）；平台最小滑塊的實體換算另在原生證據記錄。每頁狀態須提供來源量測的說明或路徑。

有獨立情境清單時，加上 `--expected-coverage <檔案路徑>`。清單為 JSON 陣列，每筆有 `page`、`size`、`owner`、`state`，量測也須填這四欄。檢查程式用清單判定漏測與重複量測。檢查接點的原生驗收入口會產生這份清單並自動比對。

## 原生／正式 EXE 交付

從相同布局資料重新確認各區的 owner 與實際幾何。短內容 → 確認沒有無用途捲軸；長內容 → 用滾輪、捲軸與鍵盤到首末 → 確認只有目標區移動，固定操作不動、最後一行及焦點可達。縮放、展開及返回後重做。截圖與自動幾何檢查不能代替這些操作；沒有實際操作證據就保留未驗收狀態。

## 2026-11-11 已知失敗批次

`docs/ui-review/v2-manuscript-tools-design` 的舊繪圖模板依頁面類型畫捲軸，而非計算溢出，且滑塊長度固定。圖片與連結檢查曾通過，不代表捲動設計通過。此批須重整布局／捲動資料並重出圖；修正前不可作為已符合全部UI規範的核准依據。這項狀態另在該批索引與實作交接記錄。
