## 現況與方向

現況主介面上方是來源／校對／語音試聽入口，左側選批次，中間並排原文與校對稿，右側編輯／AI／確認頁籤，儲存位於上方。使用者必須在上方、右側頁籤和編輯區間往返，確認不是明顯的流程步驟；右側常駐工具也壓縮文字閱讀。

提案保留米白、紙面、深綠與原生桌面工具語彙，改變資訊排列：固定上方四步「1匯入來源 → 2校對文字 → 3確認朗讀稿 → 4試聽與製作」，左側製作批次固定，中間工作區依步驟切換，下一步固定在下方右側。頁籤是可返回的流程導航，不是強制每次從第一步重走；批次各有自己的狀態。

## 圖一：校對

[大圖](01-proofreading.png)。視線與操作是左選批次 → 中間讀擷取原文 → 右邊編輯校對稿 → 下方儲存。取消常駐右工具欄，把PDF原頁對照、換行整理、AI校對（選用）、搜尋／取代放在稿件上方。AI候選仍須明確採用，不自動改稿，也不把AI設定變成人人必經步驟。主要動作是「儲存並前往確認」，次要動作是「只儲存校對稿」。

圖上淡綠修正標示為設計示意，目前一般編輯器沒有這種常駐差異標示；若採用需另行確認比對基準與關閉方式，不能當作已具備功能。實作也可先不加這種標示。

## 圖二：確認

[大圖](02-confirm-reading.png)。同一本書、同一個批次，流程導航進入第三步。唯讀全文預覽在左，儲存版本／來源未處理數／朗讀確認狀態在右，最後明確按「確認朗讀稿並前往語音設定」。不額外加重複確認勾選框。該動作保存朗讀快照，再進入語音設定，不傳送文字或開始合成。若內容仍需改動，可直接返回校對。

圖上是未確認但可確認的狀態，不是假裝已確認。若有未處理來源異常，需顯示具體原因、檢查入口並停用確認；本圖以未處理0項示意。改稿後取消目前確認，舊朗讀快照／成功成品保留。

## 與語音畫面的銜接

第四步連接已討論的多服務語音流程：選服務 → 模型可選可填 → 選音色與節奏 → 編輯短文試聽 → 正式MP3／SRT。預設正常路徑是校對與確認後往右前進，但未確認前仍能先試聽；不能因四步視覺順序就把短文試聽鎖住。只有正式合成要求已確認朗讀稿。服務採目前的Google Gemini TTS API key、Fish與Edge資訊，不回退成舊Google Cloud專案／ADC方案。

第一步匯入詳細畫面與第四步嵌入主介面或開獨立語音視窗，本次未另繪，也未決定實作方式。影片未完成功能不放在主要流程中假裝可用。
