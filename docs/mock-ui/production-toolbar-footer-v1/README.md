# 音訊頁工具列與底部空間 Mock

設計提案，尚未修改產品或正式封裝。依 AGENTS.md、docs/ui-components.md 與 frontend-visual-qa 製作。

## 本次範圍

- 流程按鈕改用工作區尺寸角色，選取前後高度固定；與相鄰匯入、管理及任務控制項對齊。Mock 統一為 36 設計像素；正式 Tk 實作沿用共用 Workspace 樣式，不以 PNG 像素硬寫尺寸。
- 原底部兩行狀態區改為全寬固定操作帶。文件摘要收成一行；返回及重新開始放左側，成品與下一步放右側。狀態、同意傳送及成品可用性仍保留於音訊工作區。
- 一般視窗操作同列；900×640 時分兩列，避免壓縮標籤或水平捲動。
- 朗讀稿與設定沿用原地替換區塊清單的方式。返回保留選取與捲動位置，不另開視窗。
- 保留既有按鈕名稱、成品操作選單及停用狀態。已載入專案的完整訊息由既有訊息記錄查看。

## 確認設計後的驗收

1. 開啟音訊製做 → 比較流程按鈕與同列控制項上下邊界 → 確認同角色高度差不超過 2 個 Tk 座標像素。
2. 還原至 900×640 → 檢查清單 → 確認至少可見 6 列，且每個必要操作完整可見。
3. 按下朗讀稿與任務設定 → 檢查內容區與底部操作 → 確認原地切換且底部不移動。
4. 返回區塊清單 → 檢查選取與捲動位置 → 確認保留。
5. 捲動長清單至末列 → 檢查操作列 → 確認僅清單捲動。
6. 取消同意傳送 → 按下製作 → 確認未送出文字。
7. 顯示 429 錯誤 → 按下狀態詳情 → 確認完整錯誤可讀，返回後保留內容狀態。
8. 檢查正常、選取、焦點、忙碌與停用狀態 → 確認按鈕尺寸穩定且選單箭頭僅出現一次。
9. 執行原生回歸測試 → 檢查 dist/ebook2mp4 正式畫面 → 分別保留測試結果、尺寸量測及畫面證據。
