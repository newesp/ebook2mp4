# TTS 限速、原因分類與持久冷卻

2026-10-31。依核准的三項改進實作，不調整版面。

## 行為

`tts_control.py` 使用本機 SQLite 交易保存請求預約與服務冷卻；試聽、正式製作及不同程序共用記錄。範圍依服務、API 金鑰雜湊與模型區分；同一金鑰的不同服務設定檔不會繞過限制。明文金鑰、書稿及原始錯誤回覆不寫入使用記錄。

收到 429 時最多讀取 64 KiB 錯誤資料，以已知關鍵字分類為每日／期間配額、帳務／支出限制、頻率／同時請求限制，或無法辨識。只呈現固定分類文字，不顯示原始回覆。配額與帳務類立即停止自動重試；其他錯誤沿用既有有限重試。

服務提供 `Retry-After` 時保存其冷卻期限；期限前再次續作不送出 HTTP 請求，並顯示預計可重試的本機時間。429 未提供有效等待時間時採 60 秒本機保護冷卻，訊息標示「本機保護」，不假稱這是服務額度重置時間。變更服務帳戶或模型使用獨立記錄。正在等待限速預約的請求在送出前會再次檢查冷卻。

本機每分鐘請求限制預設 60（每秒一筆），這是保守的應用程式預設值，**不是官方或帳戶實際額度**。可依服務後台資料設定以下檔案，保存後下一次請求即讀取：

`%LOCALAPPDATA%/ebook2mp4/voice/tts-limits.json`

```json
{
  "gemini-tts:gemini-3.8-flash-tts": {"requests_per_minute": 10},
  "fish-audio:s2.1-pro-free": {"requests_per_minute": 2}
}
```

上例數字僅展示格式，請填帳戶實際額度或更低值。必須為有限正數。不同帳戶共用此設定值，但請求使用記錄分開計算。限速預約等待超過 300 秒會停止本次工作，不長時間保持忙碌。

服務可能按 token、字元、每日用量、同時請求數或整個專案限制；本次預先限速涵蓋請求頻率，沒有推測 token 數或每日剩餘額度，也不能計入其他應用程式用量。Google 同專案不同金鑰在本機分別記錄，服務端仍可能合併計算。已保存的冷卻在期限前會阻擋請求，即使服務帳戶已提前恢復；這是避免反覆無效續作的預期行為。

## 驗證與使用

新測試 `test_tts_control.py` 驗證原因分類、畸形／過大回覆、持久冷卻阻擋 HTTP、同金鑰不同設定檔、帳戶／模型隔離、到期恢復、配置限速、取消與敏感資料不落盤。證據見 `tts-control-test_*.txt`。原有虛擬時間傳輸測試隔離限速層，避免把虛擬的 120 秒當成真實已過時間；限速層另由新測試直接驗證。

型別檢查與封裝紀錄見 `tts-control-typecheck.txt`、`tts-control-build.txt`。沒有使用真實 TTS 金鑰、額度或書稿進行驗證。

5 個相關測試模組合計 26 案例通過、0 跳過；26 個來源檔案型別檢查通過。封裝中 5 個相關模組與來源編譯結果一致，原生啟動與正常關閉退出碼 0。SHA-256：`d0e66914cf4eae148e8c1321663322fa9433a4e77be896703020850c28d867c9`。

新版位置：`dist/TTS-control/ebook2mp4/ebook2mp4.exe`。搬移時保留整個資料夾。

1. 舊版仍在執行時 → 取消任務 → 等待停止 → 關閉舊版。
2. 開啟新版 → 開啟原專案 → 進入「製作與成品」→ 繼續未完成區塊。
3. 服務回覆 429 → 檢查原因分類與等待時間。
4. 冷卻期間再次續作 → 檢查顯示冷卻尚未結束 → 確認不再送出文字。
5. 冷卻到期 → 再次續作 → 確認已成功的音訊仍被重用。

本次程式啟閉與封裝來源比對見 `tts-control-package.json`；清理結果見 `tts-control-cleanup.json`。
