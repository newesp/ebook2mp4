# 音訊訊息列、背景任務列與關閉修正

2026-11-10。依已核准的 `docs/mock-ui/audio-status-taskbar-v4` 實作。正式成品位於 `dist/ebook2mp4/ebook2mp4.exe`。

## UI 結果

- 「更新 MP3／SRT」移除箭頭。
- 音訊頁文件摘要占整列，不保留右側載入訊息欄。例行載入與暫存訊息仍可由訊息記錄查看；開啟專案使用既有短暫提示，自動重載也提供提示。「原始來源檔不會被改寫」補至既有專案位置與來源資訊。
- 重要或可處理的全域訊息仍使用全寬獨立列顯示，不會因合併摘要而隱藏。測試包含模擬儲存失敗。
- 正在查看執行中任務時，使用頁內進度，不顯示重複的返回任務列。
- 離開任務後，背景列分別顯示進度摘要與「返回任務 →」。背景列位於主視窗第 4 列，底部操作區位於第 5 列；不再共用同一個格子。隱藏背景列時，其高度隨之釋放。
- 背景工作結束或取消時更新狀態，不持續顯示舊的「製作中」。同書其他音訊批次的衝突製作及重新檢查操作會停用。

## 關閉問題的重現與原因

`tests/test_close_lifecycle.py` 經由實際 `WM_DELETE_WINDOW` 命令檢查視窗是否在限定時間內消失。最小重現只需開啟批次影片頁，無須播放或執行合成。

- `close-minimized-red.txt`：修正前主視窗仍存在，重現失敗。
- `close-probe.txt`：原行為在三秒內進入關閉 56 次，影片清理回呼執行 0 次；沒有影片播放暫存或解碼工作。將同一頁關閉改為僅啟動一次後，清理回呼執行 1 次，視窗正常結束。

原因是主視窗等待各頁關閉時會重複要求影片頁關閉；影片頁每次取消並重排自己的清理計時器，導致回呼一直被延後。

修正讓關閉請求可重複呼叫但不重啟清理：已進入關閉的製作頁繼續原清理程序，影片頁忽略重複關閉請求；主視窗只保留一個關閉重試計時器，並於銷毀時清除。沒有強制終止使用者程序。

## 自動驗證

41 項不同測試最終通過：

- `regression.txt`：22 項，包含五個關閉情境、正常／最小視窗、錯誤訊息保留、背景列不重疊及空間回收、跨頁返回、同意阻擋、音訊播放與保存重試。
- `related-tests.txt` 中專案重載、總影片、批次影片 11 項通過。
- `notifications-final.txt`：通知 8 項通過。

擴充檢查最初發現通知焦點測試失敗。`notification-fixture-probe.txt` 證明在顯示通知之前，原測試的編輯器就未顯示，焦點也不在編輯器。校正測試，使其先載入隔離書稿，再分別驗證提示前後焦點；未修改通知顯示功能來遷就此案例。初次失敗記錄保留，以最終通知結果為準。

關閉情境包括：音訊頁、從音訊返回試聽頁、影片頁、服務頁，以及實際模擬合成等待中。最後一項確認工作取消且 `.production.lock` 已釋放；原有關閉自動保存草稿的案例也通過。

## 原生畫面

使用隔離合成資料，未傳送使用者書稿。

1. 在目前執行任務查看進度 → 確認頁內進度及取消操作可見，沒有重複返回列。`native-running.png`。
2. 切到文稿頁 → 確認背景任務列位於操作區上方，沒有覆蓋按鈕。`native-background.png`。
3. 按下返回任務 → 確認回到原任務，背景列隱藏且表格取得空間。`native-returned.png`。

`native-metrics.json`：1280×720、173 塊，清單完整可見 17 列；任務選擇與相鄰按鈕皆 37 個 Tk 座標像素，選單指示符只有一個。1360×820 與 900×640 的尺寸與必要控制項可達性另由原生回歸涵蓋。

## 正式封裝驗收

1. 開啟音訊製做 → 重新檢查目前稿件與設定 → 確認更新按鈕無箭頭，摘要不再分配右側載入訊息欄。`package-update.png`。
2. 按下製作 MP4 → 確認進入先前會造成關閉卡住的批次影片頁。`package-video-before-close.png`。
3. 按下視窗右上關閉按鈕 → 確認 EXE 程序正常結束且結束碼為 0。`package.json`、`package-close-final.json`。

`package-close-observation.json` 保留按下當下的觀察；視窗清理為非同步，最終關閉判定以程序結束結果及後續空視窗清單為準。`startup-state.txt` 額外確認載入提示後啟動狀態仍為 `zoomed`。

原生執行中背景切換使用離線替代服務；正式 EXE 驗收沒有對雲端送出合成工作。本次未驗證真實雲端服務可用性。
