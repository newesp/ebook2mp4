# 超長服務等待與續作狀態同步

2026-10-31。修正使用者回報的「等待 77813 秒後重試 · 區塊 43/173 · 完成 42 · 失敗 0」，以及清單仍顯示區塊 39 失敗的情形。

## 原因

前次取消 60 秒硬性失敗限制後，沒有另設自動等待總額。服務指定 77,813 秒時，製作任務會保持忙碌約 21 小時 37 分，下一次失敗還可能再次等待。狀態文字只顯示收到的原秒數，沒有倒數。

製作頁續作時，只有狀態列取得新任務進度，清單仍顯示上次保存的失敗列。此時選取舊失敗列，也會與共用狀態列的即時進度互相覆寫。這能造成「清單區塊 39 失敗」與「目前區塊 43、失敗 0」同時出現。

原始服務的 HTTP 回覆未由使用者提供。僅憑秒數無法確認是否為日配額、其他限流或服務維護；本次沒有呼叫使用者的遠端服務。

## 修正

- 每個區塊的自動等待總額最多 300 秒。若下次等待會超過餘額，立即結束本次製作，不縮短服務指定的等待時間後繼續自動送出。
- 顯示原 HTTP 原因、服務要求的秒數、自動等待上限，以及「已停止自動重試」與後續操作說明。成功音訊快取保留；使用者可在服務恢復或處理配額後手動續作。
- 120 秒等短等待仍可重試與取消。以單調時鐘計算目前倒數，不因系統日期調整而跳動。
- 續作開始立即清除舊失敗顯示，後續同步更新各列狀態、嘗試次數及摘要。更新既有列以保留選取與捲動位置。執行期間，點選清單不再用歷史錯誤覆蓋目前進度；停止後仍可查看各失敗區塊的真實原因。

修改範圍為 `voice_media.py`、`narration.py`、`narration_desktop.py`。不調整主視窗版面、不更換服務或模型，不變更朗讀稿與快取識別規則。
