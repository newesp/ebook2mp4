# 製片失敗診斷與 FFmpeg N/A 進度修正

2026-11-05。使用者回報 3840×2160／25 fps 背景在批次製片進度 0 時失敗。唯讀檢查指定專案的兩次失敗紀錄，均停在製作 MP4。沒有修改書籍專案、原始媒體、音訊或字幕；沒有新 TTS。

## 根因與修正

FFmpeg 在編碼器尚未輸出第一個封包時會回報 `out_time_us=N/A`。既有程式直接呼叫 `int('N/A')`，引發 ValueError；通用背景工作把非預期例外轉成 TTS 錯誤，再被製片工作改成沒有原因的泛用錯誤。素材本身可正常製片。

已先以進度輸入重現，`red-user-env.txt` 明確捕捉 ValueError。再以使用者素材與同批音訊的 3 秒片段驗證：原始 FFmpeg 進度確實包含 N/A，工具結束碼 0；證據 `original-progress.txt`、`original-probe.json`。透過修正後同一個 `TotalVideoJob.command` 再跑原素材，成功輸出 90 格，見 `actual-fixed.json`。只輸出至本次工作暫存，完成後清除，未產生使用者書籍的新正式版本。這是短段驗證，沒有宣稱完成整批長片的最終製作。

未知進度時間現在會自動略過，保留當前進度並繼續製片。真正的工具錯誤會取得 stderr；以獨立暫存檔接收以避免管線塞住，僅保留最後 16,384 bytes 作為診斷，關閉或取消皆釋放暫存。音訊解碼、無聲背景準備、編碼及最終完整驗證共用診斷命令流程。

區分空間不足、權限或檔案占用、記憶體或資源不足、工具缺少或不相容、素材損壞、逾時及未分類編碼錯誤，提供操作步驟。不會未經確認刪除資料、自動更換素材或重合成語音。未預期的 Python 例外保留類型與原因，不再偽裝成網路錯誤。

診斷保存在任務 `progress.json` 的 `diagnostic`，包含 category／message／detail／phase，失敗後及重開專案可回查。既有「來源詳情」顯示最近一次任務的診斷，現有狀態列顯示處理步驟；不改版面、不新增視窗。舊任務沒有診斷欄位仍相容，舊泛用錯誤無法回溯取得當時已丟棄的 stderr，需以新版重試才有新診斷。

## 使用方式

1. 關閉舊版程式 → 開啟新版 `dist/ebook2mp4/ebook2mp4.exe`。
2. 開啟原書籍 → 選原批次 → 進入批次影片 → 按「重試製片」。
3. 檢查製片進度 → 確認不再因初始 N/A 中止。
4. 若仍失敗 → 讀取狀態列步驟 → 按「來源詳情」查看失敗階段與原因。
5. 依步驟處理 → 按「重試製片」→ 確認舊成品在失敗／取消時保留。
