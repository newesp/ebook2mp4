# Ticket #13 補驗與窄版試聽修正

2026-11-18。Ticket #13 的目標是讓文稿、設定、音訊、合併及影片共用同一主視窗的導覽、標頭、內容與操作列。D 補驗頁面自身的功能和狀態，E 補驗跨頁與正式 EXE。B／C 的全頁接入已有 [11-13 證據](../v2-shell-refactor/README.md)。本批沿用既有操作流程，整張票仍開啟。

試聽頁在 900×640、13pt 下，文字框會被固定狀態和內距擠出可見區。精簡字數提示、收起無試聽結果時的提示、減少試聽框垂直內距，並在忙碌時優先顯示進度和取消。完成後會恢復上次試聽結果的摘要。待命時文字框高 45 Tk px，忙碌時高 23 Tk px，兩狀態均可見。原有文字操作按鈕同寬，兩組水平淨距為 4，文字框上方淨距為 8。見 [失敗版](voice-before-900x640-13pt.png)、[待命](voice-after-900x640-13pt-idle.png)、[忙碌](voice-after-900x640-13pt-busy.png)、[尺寸與狀態量測](voice-native-states.json)。

## 剩餘工作與人工覆核

- #13 的下一步先釐清正式 EXE 的 TXT「放棄預覽」滑鼠操作，並單獨重跑 OCR 忙碌、共用路由與接點基準線。再補完各頁異常／取消及正式 EXE 逐頁矩陣。真實雲端服務與 Kokoro 原票保留各自的驗收條件。
- 使用者若要先確認日常操作，可用測試書籍副本走「文稿 → 版本紀錄 → 看差異 → 返回」及「試聽與製作 → 語音設定與試聽 → 縮小視窗 → 確認文字、儲存與下一步可用」。有實際聽感、音量、發音或 Windows 縮放差異再回報。
- #13 的剩餘矩陣結束後，下一項是 K09／#11 的乾淨 Windows 離線驗收。使用現有正式主程式及 Kokoro 語音包，在未安裝 Python、無模型快取的環境完成安裝、試聽、批次 MP3／SRT、全書音訊及清理。K01 可行性與歷史離線整合已有證據；音色聽感由 [試聽表](../kokoro-k01/quality-review.md)覆核。見 [K09](../../tickets/kokoro-cpu/09-packaged-offline-book-acceptance.md)。
