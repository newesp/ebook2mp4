# Gemini TTS 429 恢復交付

2026-11-05。正式程式：`dist/ebook2mp4/ebook2mp4.exe`。

Gemini 的暫時 429 使用獨立的 30 次／每區塊 1800 秒恢復上限，以及 5、10、20、40、60 秒基底加 jitter 的退避。服務等待時間優先，過長等待立即停止並保留進度。一般網路錯誤仍使用原有三次限制。

新增 Gemini 專用共用 SQLite 限速排程；預設 5 RPM，可由原本的 tts-limits.json 覆寫。429 後間距加倍，10 分鐘無新 429 後才恢復設定值。各程序等待後重新競爭發送時段，取消不留下未使用的預約。

解析 Retry-After 及可選 google.rpc.RetryInfo；明確每日配額／帳務原因停止自動重試。泛稱 quota_exceeded 保留未知分類。等待秒數不單獨作為每日配額證據。未到期的舊冷卻保守處理，不刪除舊紀錄。未增加 UI 版面。

## 驗證

最小案例在修正前以「區塊已嘗試 3 次，服務仍未恢復」失敗；修正後可在第四次 429 後繼續第五次並成功。

build.txt 保存建置結果。建置依賴安裝到專用暫存目錄；FFmpeg／OCR 資源從既有正式成品重用。launch.json 證明正式程式啟動後正常關閉，退出碼 0。package-hash.json 保存成品 SHA-256。

## 使用與限制

關閉舊程式 → 開啟 dist/ebook2mp4/ebook2mp4.exe → 開啟專案 →「試聽與製作」→「製作與成品」→「繼續未完成區塊」。

等待中 → 檢查倒數 → 確認完成數繼續增加。要停止時 → 按「取消任務」→ 確認已取消。長冷卻停止時 → 檢查原因與最早重試時間 → 處理配額後再續作。

本機排程按金鑰及模型分組，無法掌握同一 Google 專案的其他金鑰、電腦及外部程式。服務提示的最早重試時間不代表成功保證。無提示的配額問題仍需使用者查 AI Studio。
