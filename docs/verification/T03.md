# T03：人工校對、外部重載與朗讀稿確認

2026-10-25（Asia/Taipei）。依據 Spec v1.1、GLOSSARY、ADRs 與 `.scratch/pdf-txt-audiobook-video/v1.1/issues/03-proofread-confirm-reading-draft.md`。

## 完成內容

- 真實 Tk 編輯器支援完全相符搜尋、循環尋找下一處、取代一處、全部取代、復原及保存。顯示字元數、以空白行分隔的非空段落數、版本與儲存狀態。
- UTF-8 匯出包含未存編輯，採排他建立，拒絕覆寫來源或既有檔案，不改專案儲存狀態；寫入失敗清除本次不完整匯出。
- 外部稿重載沿用嚴格解碼、編碼切換、預覽及異常字元核對。未存稿可保留專案內副本、明確取代或取消；新稿與副本同次發布索引，失敗保留編輯器及前次成功專案。
- 來源原始位元組、UTF-8 校對版本、副本與朗讀快照獨立保存；沒有繁簡轉換、摘要、改寫或插入朗讀頁碼。TXT 明示無 PDF 頁碼。
- 明確確認先保存校對稿，再建立帶識別、校對版本、時間與 SHA-256 的不可變快照。編輯、復原及重載取消該批目前確認；舊快照及其他批次不變。改名、排序與保存相同文字不取消有效確認。
- 空稿及未處理來源異常不得確認，UI 列出原因並可明確略過。公開工作流程提供記錄、處理／略過與確認阻擋規則，供後續 PDF／OCR 接入；本張未實作 PDF 偵測或 OCR。
- 唯讀版本視窗可查閱歷史朗讀快照與未存稿副本的完整文字、路徑及雜湊，並選取複製。開啟專案驗證快照／副本與目前確認的一致性；歷史資料不自動回收。
- 另一視窗修改索引後，舊工作流程不能繼續取得「目前確認稿」，須重開；明確指定歷史快照仍可唯讀查閱。

## TDD 與驗證

沿用 Spec 已確認的 `ProjectWorkflow` 公開介面與真實 Tk UI 連接兩個邊界。先重現缺少確認／匯出重載、來源異常未阻擋／快照未驗證、UI 無搜尋與確認工具、工具區不支援滾輪，以及多視窗舊確認仍可讀取的失敗，再逐項實作。另加入衝突選項、故障復原、版本查閱與回歸驗證。

最終命令（工具先依 packaging/requirements-dev.txt 安裝至 `.scratch/build-tools`）：

```powershell
python -m unittest discover -s tests -v
$env:PYTHONPATH = "$PWD\.scratch\build-tools"
python -m mypy ebook2mp4 --check-untyped-defs --cache-dir .mypy_cache
python -m compileall -q ebook2mp4 tests packaging/build.py
python packaging/build.py
```

結果：**31／31 tests 通過**（23 個工作流程、8 個真實 Tk，34.523 秒）；mypy 2.4.0 檢查 4 個來源檔案無問題；語法編譯及 PyInstaller 建置成功。環境為 Windows 11 10.0.26200、Python 3.14.3、Tk 8.6、PyInstaller 6.22.3／hooks 2026.9。

真實處理包含暫存書籍專案、檔案讀寫、各支援編碼、SHA-256、原子索引發布、排他匯出及 Tk 控制項／事件。替身僅限原生選檔／輸入／訊息對話框及檔案故障注入。桌面截圖另驗證真實原生衝突提示與滾輪。沒有使用 PDF／OCR、Gemini、Edge-TTS 或媒體服務，不記為這些服務的驗收。
