## 行為與保存

- 每次最多 6,000 個送出的來源字元，優先保留空白行段落，超長段依句尾／空白切分，無適當邊界才按上限切開。分隔空白留在本機；來源字元範圍連續覆蓋所選範圍，段落覆蓋所有非空白原文，不重複。這是 Gemini 工程分段，並非尚未實作的 TTS 語音切塊。
- `start_gemini_review` 先原子保存來源版本與請求計畫，再啟動背景工作。每個成功或失敗請求後，原子替換該工作獨立的進度檔；內含完整快照與 SHA-256，重開時驗證校驗碼、來源參照、原文／範圍、請求順序與候選完整性。候選進度寫入不碰稿件索引，不與 UI 人工改稿互相覆寫。
- `finish_gemini_review` 發布不可變完整記錄，再清理所屬進度檔。進度寫入失敗會停止後續請求，記憶體候選可重試最終保存；成功保存後依請求實際狀態顯示結果，不再誤報未保存。Windows 短暫分享衝突只在背景有限重試。
- `start_gemini_retry(batch_id, review_id, failed_only=True)` 僅重送失敗請求；預設 `False` 處理所有非成功請求，含未送出、取消及中斷範圍。保留相同來源版本、模型、字體／標點規則、既有成功候選與決定，不改送目前新稿。
- 成功段可在部分結果中逐段採用／拒絕；批次採用只處理有候選且待確認的段落，沒有結果的段落不能誤採用。撤回、朗讀確認失效、選外內容保留及相對路徑規則沿用 T07。人工改稿後禁止續作、採用及撤回舊版本，舊候選仍可比較。
- 取消不收晚到結果，成功候選不清空；關閉等待目前 HTTP 連線結束並釋放（既有單次連線 timeout 30 秒），保留失敗保存時明確捨棄的出口。直接中斷程序後，最後成功的進度仍可開啟及續作。程序在原子檔案替換前中斷，沿用 ADR 的前次成功版本及未參照中斷檔規則。
- 專案格式仍為 v1；T07 記錄可讀，沒有請求計畫的舊候選需重新送出，不暗建重試範圍。T08 工作進度請用 T08 或更新版續作。金鑰不寫入記錄／日誌／書籍專案。
