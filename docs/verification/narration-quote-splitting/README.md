# 朗讀稿引號切分修正

## 問題與原因

使用附件 ch3.txt（6,843 字元）呼叫 `narration.plan(text, DEFAULT_SETTINGS, 'r', 'b')`，修正前可重現：

> 朗讀稿有過長且無法安全切分的引文、網址或句段。請加入自然分句後重新確認。

附件混用彎引號、直引號，也有以左引號結束對話的情況。引號堆疊無法閉合，後續自然句號被忽略。超過服務請求長度時，規劃階段拒絕開始製作。

## 修正

優先沿用原有切分，保留正常短引文。原有切分找不到合法位置時，允許沿引文內句號或子句標點切分。網址、括號與無自然分句的超長文字仍受保護。原文不改寫。分段規則版本更新為 rhythm-block-v3。

- 新增混用引號的完整製作案例：1 項通過。
- 附件全文經確認朗讀稿、開始製作、完成製作流程：11 次請求，最大 2,940 bytes；原文完整保留；MP3/SRT 均產生；製作鎖定釋放。
- 語音服務使用模擬回應，音訊轉檔使用真正 FFmpeg。本次未驗證線上服務可用性或真實朗讀品質。

測試資料與暫時成品由測試清除。附件未複製至專案。
