## 1. UI scroll

- **未測**　短內容／空狀態 → 確認完整容納時沒有捲軸、空軌道或殘留可捲範圍；空狀態提示可見。
- **未測**　剛好容納、溢出及長內容 → 確認捲軸只屬於實際溢出的區域，滑塊比例及行程符合內容範圍。
- **未測**　捲到首末 → 用滾輪、捲軸及鍵盤確認完整內容與最後一行可達；標頭、導覽及主要操作保持固定。
- **未測**　長內容頁 → 空狀態頁 → 返回 → 確認未殘留前頁的捲動範圍或軌道。
- **未測**　改變視窗、字級及展開／收合區域 → 確認重新計算溢出，沒有裁切、非必要水平捲動或整頁包內部捲動。

## 2. UI／元件風格一致性

- **未測**　比較同組 Button、Entry、Combobox → 確認字型、字級、邊框、內距及互動狀態一致，主要／次要操作依既有共用樣式區分。
- **未測**　比較同一表單欄位位置的按鈕與輸入元件 → 確認外框寬、高相同，差異不超過 2 個 Tk 座標像素。例如「下載／安裝 OCR 模型」按鈕須與同欄其他 input 同寬，並與旁邊「旋轉角度」輸入元件同高。
- **未測**（部分量測見案例 1）　比較同組同角色文字按鈕 → 記錄每個原生外框寬、高，確認共用尺寸且文字完整；不得僅以相同 style 名稱判定通過。試聽區「使用固定試聽範例／帶入選取文字」為必要案例。
- **未測**　檢查預設、焦點、停用及忙碌狀態 → 確認不因狀態切換改變尺寸，文字與圖示完整可辨，下拉指示只出現一次。

## 3. UI／元件整齊對齊

- **未測**　比較左右同列控制項 → 確認上緣、下緣及高度一致，差異不超過 2 個 Tk 座標像素。欄位標籤與輸入區分開對齊，避免按鈕對到標籤列。
- **未測**　比較上下同欄控制項 → 確認左右邊界一致，欄距、列距遵循共用規範。
- **未測**（部分量測見案例 1）　比較每組相鄰動作 → 記錄「右元件左緣－左元件右緣」，確認符合元件規範的水平淨距；底部「儲存設定／前往音訊製做」為必要案例。
- **未測**（部分量測見案例 1）　比較操作列與下方內容區 → 記錄「內容區上緣－操作列最下方控制項下緣」，確認符合元件規範的垂直淨距；試聽區兩個文字按鈕與Text為必要案例。
- **未測**　比較相鄰區塊 → 分別量測標頭帶與內容起點，確認齊頭；固定操作列整齊，沒有重疊、裁切或祖先容器遮擋。文件列表／檢查接點的量測元件與正常布局路徑依[元件規範](../../../ui-components.md#文件列表與檢查接點的兩條基準線)。
- **未測**（部分量測見案例 1）　在最大化、1360×820、1280×720、900×640及適用字級／列表收合狀態重查 → 確認尺寸、對齊和操作可達性仍符合上述要求。
