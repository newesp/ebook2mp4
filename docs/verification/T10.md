# T10 — 已確認朗讀稿產生批次 MP3／SRT

2026-10-27。票稿：`.scratch/pdf-txt-audiobook-video/v1.1/issues/10-confirmed-draft-mp3-srt.md`。起點 `61c3436`；實作 `ab13d69`，審查修正 `6253fa9`、`e513d7d`、`34c2b24`。沿用已核定的 ProjectWorkflow 與真實 Tk 測試邊界。

## 操作

1. 選批次，儲存並確認朗讀稿。
2. 開啟「語音試聽」，選擇音色與語速，儲存本批設定。
3. 按「批次 MP3／SRT…」。核對顯示的已確認全文與設定。
4. 勾選同意傳送至 Microsoft Edge 線上語音服務。
5. 按「產生 MP3／SRT」。完成後可播放、停止、另存兩檔或開啟資料夾。

未確認稿不能正式合成。開始前若稿件或設定已改，重讀內容並清除同意，須重新核對。視窗固定書籍／批次，主窗切換後不允許從舊視窗啟動新任務。開始後可繼續校對，這次任務使用原快照。

另存會建立新的具名資料夾，內含 `narration.mp3`、`narration.srt`；不覆寫既有目的地。專案成品保留在專案內，使用相對路徑與 SHA-256。上次成品顯示實際音色、時長、完成時間及區塊數；改稿後仍可播放舊成品，不宣稱它代表新稿。

## 行為與保存

- `start_narration(batch_id)`：驗證目前朗讀確認、明選音色及 FFmpeg；固定全文、朗讀識別、語音設定與規則。原子保存計畫後啟動背景任務。回傳 `state/cancel/wait` 工作。`state` 提供階段、目前／總區塊、完成／失敗數，不提供虛構百分比。
- `finish_narration(job)`：全區塊成功、MP3 完整解碼與字幕完成後，才原子發布專案成品索引。`discard_narration(job)` 釋放停止的工作；失敗／取消刪除本次音訊暫存，保留計畫與進度記錄。已發布音訊不會被後續捨棄刪除。
- `narration(batch_id)`／`narration_path(batch_id, 'mp3'|'srt')`：取回上次成功結果並檢查檔案雜湊。`export_narration(batch_id, new_folder)`：在同層暫存完成兩檔，再發布至新資料夾。
- `narration_runs(batch_id)`：讀取已保存的不可變請求計畫與進度。區塊記錄含穩定識別、順序、實際文字、段落分隔符、內容／設定／規則雜湊、狀態、嘗試數與實測時長。失敗前的成功區塊不能讓整體報完成。
- 跨視窗使用排他 `.production.lock`，持有至保存或捨棄結果。硬中斷留下鎖檔時，明確提示先關閉所有視窗，再移除鎖檔並重開。不自動猜測殘留鎖是否安全，也不宣稱已實作 T12 斷點續作。
- 保存後清理鎖檔失敗會提示重試；已發布成品有獨立保護標記。再次保存不重做合成；關閉／捨棄也不會刪除已發布檔案。

## 切分與時間軸

保留空白行段落，整段在限制內時不拆。必要時依完整句尾、分句、詞間空白的順序選安全邊界；每個請求最多 3,000 escaped UTF-8 bytes，低於固定 Edge SDK 自動切分的 4,096 bytes，避免 SDK 再隱性硬切。英文頭銜／縮寫、數字小數、網址及段內成對引號／括號保護；省略號後不作技術切點。引文跨自然段落時仍沿原段落邊界，與 T09 契約一致。

無法在服務限制內安全分開的單一長詞、網址或段內引文會在連網前拒絕，提示加入自然分句後重新確認，不會暗改、漏字或硬切。服務不支援的控制字元也須先改稿。精確保存分隔符，計畫可重組為原確認全文。

句尾額外 0 ms；段落額外 500 ms；同邊界不疊加；末段不補。每個服務回應完整解碼成 24 kHz 單聲道 PCM，不裁頭尾、呼吸或尾音。以實際 frame 數累計時間，插入 PCM 靜音後再統一編碼 MP3。字幕採完整區塊的實測開始／結束時間，UTF-8 編碼；不虛構逐字精度，新增靜音期間無字幕。整個長區塊可有多行字幕，字幕閱讀密度與人工朗讀品質仍須驗收。

每塊網路／服務錯誤最多 3 次嘗試；每次請求有 90 秒上限，區塊解碼有 30 秒上限，整批沒有短文試聽的 90 秒總限制。整批組裝／全解碼各有 1 小時上限。取消會等服務與媒體子程序退出；重複取消不打斷清理。
