# K06 連續試聽與程序清理

2026-11-21。對照 [#8](https://github.com/newesp/ebook2mp4/issues/8)，修正閒置計時器回呼過期後仍可卸載新模型的問題。

舊計時器回呼若已進入執行緒並等待引擎鎖，取消計時器也無法阻止該回呼繼續。當下一次試聽完成，過期回呼可能把新的閒置模型卸載。修正後，每次工作與卸載都會更新計時識別，僅目前計時器能執行卸載。

## 本次驗證

使用公開 ProjectWorkflow 入口及小型協定測試包，啟動真實 Windows Python 子程序。測試 worker 另外建立後代程序，合成內容使用短 PCM，驗證重點為程序生命週期。CPU 模型品質與載入速度採既有真實模型證據。

- 連續兩次試聽沿用同一工作程序，載入次數維持 1。強制執行先前已取消的計時回呼，模型仍保持載入。[修正前失敗](timer-red.txt) · [最終通過](lifecycle-final.txt)
- 合成時間超過縮短的閒置期限，程序仍存活，移除語音包被阻止。
- 取消合成後，使用 Windows 程序控制代碼等待 worker 及後代程序結束。上次試聽記錄保留。
- worker 模擬非正常退出後，工作回報失敗，下一次試聽能正常啟動。
- 閒置期限到達及明確卸載後，worker 及後代程序都已結束，沒有殘留 `.worker-*` 目錄。再次試聽會重新載入。

最終兩項生命週期測試通過。較廣的 15 項測試中，其餘 12 項通過、1 項需真實模型包而跳過。生命週期測試首次與建置並行時，程序已在取得控制代碼前卸載，導致測試失敗。已將取得控制代碼移至合成中，之後才等待閒置退出，最終測試通過。[首輪完整紀錄](regression.txt) · [最終生命週期測試](lifecycle-final.txt)
