# T02：同書多 TXT 批次與編碼預覽

2026-10-25（Asia/Taipei）。依據 Spec v1.1、GLOSSARY、既有 ADRs 與 `.scratch/pdf-txt-audiobook-video/v1.1/issues/02-multiple-txt-batches-encodings.md`。

## 完成內容

- 一書可新增多份 TXT，每次匯入使用獨立批次識別、來源副本及校對稿；原始來源檔不改寫，不產生 PDF 頁碼。
- 左側清單可切換、命名及上下排序，名稱與順序立即原子保存；切換／新增前若有未存稿，須保存、明確捨棄或取消，保存失敗留在原批次。
- 自動辨識 UTF-8、UTF-8 BOM、UTF-16 BOM；Big5／CP950 由下拉清單手動選擇並查看真實解碼預覽。UTF-16 依 BOM 決定位元組序，缺 BOM 時不猜測。
- 嚴格解碼、不插入替代字元；錯誤時清除舊預覽、停用匯入並保留更換編碼入口。若來源本身含替代符號或異常控制字元，必須明確核對後才可匯入，原始位元組仍完整保存。此警示是有限啟發式檢查，不宣稱能自動判定所有語意亂碼。
- 保持專案格式 v1，讀取來源時使用已保存的編碼；既有 T01 專案可重開，工作稿仍以 UTF-8 獨立保存。

## TDD 與驗證

沿用已核定的公開 `ProjectWorkflow` 與少量真實 Tk UI 連接兩個邊界。依序先重現多批次拒絕、編碼參數缺漏、UI 無編碼選擇、疑似亂碼未要求確認、版本資訊不一致及損壞 ID 的失敗，再實作與驗證。

最終命令：

```powershell
python -m unittest discover -s tests -v
python -m mypy ebook2mp4 --check-untyped-defs --cache-dir .mypy_cache
python -m compileall -q ebook2mp4 tests packaging/build.py
python packaging/build.py
```

結果：**20／20 tests 通過**，約 12.9 秒；mypy 2.4.0 檢查 4 個來源檔案無問題，語法編譯及 PyInstaller 建置成功。環境為 Windows 11 10.0.26200、Python 3.14.3、Tk 8.6、PyInstaller 6.22.3／hooks 2026.9。

工作流程測試使用真實暫存書籍專案，驗證支援編碼、原文／工作稿往返、同書隔離、命名／排序／重開、來源完整及寫入保護。4 項真實 Tk 測試涵蓋建立、預覽確認、錯編碼切換、批次切換、命名、排序、未存稿取消／保存失敗保留、保存重開與版本資訊更新。

真實處理：本機檔案讀寫、解碼、SHA-256、原子發布、Tk 控制項與事件。替身僅用於原生選檔／輸入／訊息對話框及檔案故障注入。視覺 fixture 透過相同 UI 事件選擇 CP950，不取代解碼或保存服務。T02 不使用 PDF／OCR、Gemini、TTS 或媒體服務，不記為這些服務的驗收。

## 視覺與封裝

沿用 A 工作台。新增三個批次操作按鈕時，原生預設寬度會撐大側欄並擠壓中間欄位；已在同一三欄容器內設定適當的按鈕寬度。批次 Treeview 垂直捲動，完整所選名稱／版本及來源檔名置於中央換行資訊列；編輯、原文、右側工具各自捲動。

最終截圖存於 `.impeccable/review/t02/`：一般桌面 1360×780、最小支援尺寸 1040×640，以及 760×680 的失敗／成功編碼預覽，Windows 約 125% 縮放。程式預設尺寸仍為 1360×820；驗證 fixture 將高度調為 780 以完整落在目前螢幕可用區。原生 Tk 不適用 HTML detector，沒有宣稱執行瀏覽器測試。

重建成品為 `dist/ebook2mp4/ebook2mp4.exe`，附帶 `_internal`。已實際啟動重建執行檔，並由 Windows 工具讀取其桌面視窗。SHA-256：`72A752CF5C7F1D06EF97B6398F59F20954974DA28B414C5A96B748679AF892A5`。
