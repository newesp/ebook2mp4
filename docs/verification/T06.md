## 行為與保存

- UI 預設自動，公開 `start_pdf_extraction(..., mode='auto')` 逐頁讀取文字層，無字母／數字／中文字元時轉 OCR；文字層或 OCR 不足 20 個字元、替代符號及異常控制字元列待檢查。稀少文字採保守提示，沒有宣稱能判別所有圖片正文。文字層舊入口及 TXT 保留；自動模式缺工具／模型僅使需要 OCR 的頁面失敗，不回滾成功頁。
- `start_pdf_retry(batch_id, pages=[...], language=..., rotation=...)` 及 `failed_only=True` 建立獨立候選，只執行目標頁。角度為順時針 0／90／180／270；角度、實際方法、語言、模型版本及原有設定逐頁保存。非目標頁原稿與狀態保持一致，取消僅補目標頁未完成狀態。
- `pdf_extraction_pages` 回傳完整範圍的候選；`finish_pdf_extraction(..., accepted_pages=[...])` 對重試可逐頁採用，其餘沿用原逐頁原稿，原子建立新批次。原批校對稿、朗讀快照、其他批次及來源不改寫。新批以逐頁原稿組成，**不自動搬入原批全文人工校對**，介面明示並提供原校對稿全文頁籤。
- 非目標／拒絕頁沿用原明確略過；若原批已全文修改（mapping_valid=False），「已處理」可能依賴人工補稿，新批重建原稿時會重新列待確認。原稿未修改的明確處理確認可沿用。新採用且仍異常的頁面重新待確認。批次層級異常不因頁面重試消失。保存失敗保留候選供再採用；關閉捨棄釋放工作流程候選。來源內含 PDF 的驗證副本可供重做範圍，不依賴外部原檔位置。
- UI 提供逐頁清單、圖文對照、原逐頁原稿／校對全文頁籤、旋轉、本頁 OCR、只重試失敗頁及逐頁採用選項。範圍／語言／模式修改後必須執行建立候選，既有批次保持原樣。新批採用前沿用未存編輯提示；取消不失去編輯與候選。
- 失敗、空白／無字、稀少文字及取消頁阻擋朗讀確認。在原批次對照後可明確保留或略過；略過是接受異常，不自動刪校對稿文字。重試不繞過來源異常。

## 真實工具與替身

新增 `test_mixed_pdf.py` 七個工作流程案例、`test_mixed_desktop.py` 一個真實 Tk 案例，另於 `test_desktop.py` 補來源缺檔的資源釋放回歸案例。合成 PDF 包含：一頁完整文字層、一頁掃描正文、一頁僅頁碼為文字而正文為圖片、一頁空白。實際使用 PDFium、Pillow、Tesseract 5.4.0.20240606 及官方固定版模型；用已知句子核對掃描辨識，三種角度另建側轉／倒置掃描頁，再以順時針旋轉重試驗證讀回預期句子。僅數字頁的真實 OCR 回應也須列待檢查。

工作流程測試涵蓋自動分流、缺模型部分失敗、指定頁、只重試失敗、取消後非目標進度保留、逐頁拒絕、保存失敗可重試、原批校對與朗讀快照保留、異常確認及重開。Tk 測試涵蓋實際按鈕、頁圖、候選／原稿比較、未存編輯取消及保存、保留／略過、外部來源移除後重做不同範圍／模式／語言候選，以及關閉候選後專案不變。

替身僅在新測試中用環境變數指定缺引擎／模型、原生未存稿提示回答及 `os.replace` 磁碟失敗。不是 OCR 回應替身。既有完整套件仍包含 T05 的下載串流／子程序啟動故障及原生 PDF 失敗注入，與真實工具案例分開解讀。沒有將合成掃描測試宣稱為所有實體書掃描零錯字。

## 視覺驗證

Windows 原生 Tk 主視窗 1040×640、對照視窗 740×570（系統畫面縮放後截圖像素較大）。新增控制造成設定區擠壓圖文區，因此改以可展開的「範圍／OCR 設定」收合設定；既有批次及候選預設保留比較區。控制分列、文字標題隨欄寬換行，圖文各有捲軸。真實 Windows Computer Use 檢視及點擊本頁強制 OCR，確認頁碼文字 `3` 與圖片正文可同時比較，再檢視 OCR 候選讀回正文與頁碼。見 [待檢查頁](T06-sparse-page.png)、[候選比較](T06-candidate.png)。候選頁面只顯示本次狀態，不混入原批待檢查標籤。

沒有使用瀏覽器：本產品是原生 Tk。其他 DPI、輔助工具及 T23 乾淨安裝仍待人工驗收。
