# T20 驗收

正式程式：`dist/ebook2mp4/ebook2mp4.exe`。搬移時請搬移整個資料夾。

## 操作路徑

1. 開啟測試書籍 → 選「4 試聽與製作」→ 按「全書合併」→ 按「成品版本」。確認清單有總音訊、總音訊製片、批次影片合併三列。
2. 選取一列 → 按「查看來源與版本」。確認顯示成品來源、目前來源、停頓及適用的畫面設定。
3. 勾選「展開技術版本與檔案參照」。確認顯示成品識別、來源識別、專案相對路徑及 SHA-256。
4. 按「返回成品版本」→ 按「返回全書合併」。確認原選取、順序及未儲存停頓仍保留。

## 失效範圍

先準備三批 A、B、C 的有效音訊與影片。只選 A、B。分別完成三條總成品。

| 操作 | 總音訊 | 總音訊製片 | 批次影片合併 |
| --- | --- | --- | --- |
| 修改未選 C 的文字、語音或畫面 | 有效 | 有效 | 有效 |
| 修改全片背景或全片解析度 | 有效 | 待更新 | 有效 |
| 修改 A 的批次畫面或批次影片解析度 | 有效 | 有效 | 待更新 |
| 更新總音訊成功版本 | 有效 | 待更新 | 有效 |
| 修改批次影片合併解析度 | 有效 | 有效 | 待更新 |
| 修改共用選取、順序或停頓 | 待更新 | 待更新 | 待更新 |
| 修改 A 的文字或語音設定 | 待更新 | 待更新 | 待更新 |

每次操作後 → 開啟「成品版本」→ 按「重新檢查」→ 確認狀態符合表格。關閉專案後重開 → 再檢查 → 確認結果相同。舊成品的來源快照保持原值。

## 舊成品與更新

1. 選待更新成品 → 按「播放上一版」。確認播放已保存的內容。
2. 按「停止播放」→ 按「另存成品／SRT」→ 輸入新的資料夾名稱。確認媒體與字幕一起保存。
3. 選待更新的批次影片合併 → 按「前往更新來源」。確認導向需要更新的批次製作頁。
4. 先更新朗讀稿及批次音訊 → 更新批次影片 → 返回合併頁 → 重新儲存設定 → 重新製作。確認對應路徑恢復有效。
5. 取消一次製作 → 返回版本頁 → 按「重新檢查」。確認最近任務顯示已取消，成功成品仍可用。
6. 製作期間修改已選批次的文字 → 等待完成 → 檢查版本頁。確認本次成品使用啟動快照，並標示待更新。
7. 還原為 1040×640 → 開啟來源詳情 → 捲動文字。確認返回、播放、另存與更新操作可見。最大化 → 確認內容正常展開。

## 相容性與限制

舊專案的最新成功總影片會自動歸入對應路徑；之後製作另一條路徑時，兩份成功成品分開保留。舊格式未保存的語音或來源詳情不會捏造。技術參照保留原有快照。

此輪使用合成書籍、合成音調 TTS 替身及真實 FFmpeg／FFprobe。沒有使用私人書稿或線上語音服務。未宣稱長篇真書聽感、其他 DPI 或乾淨機驗收。

測試與封裝結果見同名 `T20/` 目錄。初輪測試與封裝失敗紀錄保留；以最終補驗結果為準。

## 執行結果

54 個不同相關案例最終全部通過，9 個來源完整函式型別檢查通過。使用 `tests/run_suite.py` 執行公開流程與原生案例，彙整見 `T20/test-summary.json`。1040×640／1360×800 的操作邊界檢查通過；正式 exe 另做隔離開檔、版本頁、播放與來源詳情目視檢查，見 `T20/release-smoke.json` 與三張正式畫面。

版面沿用核准草圖：版本清單與來源詳情切換；詳情區自行捲動，底部操作列固定。解決兩路影片共用最新成品欄位造成的混用；以各路徑成功成品及來源快照分開讀取。未驗其他 DPI。

封裝工具最初遇到執行中 FFmpeg 占用，後續來源比對發現舊編譯快取；停止測試並清除本輪建置與 Python 快取後重建，39 個應用模組全部符合工作區來源，兩個內附媒體工具可執行。最終封裝見 `T20/package.json`、`T20/package-check-clean.txt` 與 `T20/build-clean.txt`。
