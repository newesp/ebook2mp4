# 原生 UI 元件規範

適用所有頁面的新增、修改及驗收。與 AGENTS.md 的流程規範共同使用；尺寸與圖示規則集中於此。

## 使用

- 樣式定義以 `ebook2mp4/desktop.py:make_app` 為準；共用行為置於 `ebook2mp4/ui_controls.py`。先查既有實作，再新增變體。
- 工作區同列的 Button、Entry、Combobox 使用相容的 Workspace 尺寸；例如任務選擇使用 `Workspace.TCombobox`。Compact 僅用於次級導覽，不按頁面另造尺寸。
- 元件提供箭頭、清除或狀態圖示時，標籤只寫名稱。例如 `ttk.Menubutton(text='成品操作')`，由主題提供下拉箭頭。
- 需要新增共用建立函式時，讓預設樣式與圖示只有一個來源；避免為單一欄位增加平行元件系統。
- v2 共用外框使用 `desktop_shell.py`；文稿工具布局使用 `workspace_layout.py`。相鄰動作間距以 `TOOLBAR_GAP=4` 為來源；頁碼輸入與總頁數視為同一群組。其他頁尚未遷移時保留既有實作，不另建平行樣式。

## 驗收

### 同組按鈕與內容間距

- 同一操作群組、相同尺寸角色的文字按鈕使用共同寬度與高度。寬度依該群組最長標籤及共用內距決定，完整顯示文字；各按鈕外框寬高差≤2個Tk座標像素。圖示、刪除等不同尺寸角色須在設計對照中明確標記，不能事後用「文字較長」當作任意尺寸差異的理由。
- 相鄰動作的外框水平淨距為 `TOOLBAR_GAP`（目前4個Tk座標像素）。以實際外框量測，包含 `pack/grid` 兩側內外距的合計結果；不能只檢查程式有寫 `padx`。
- 內容上方操作列與其 Text／textarea、清單或預覽區之間，垂直淨距預設為 `2 × TOOLBAR_GAP`（目前8個Tk座標像素）。以「內容區上緣－操作列最下方控制項下緣」量測；同角色區域使用相同間距，不能以空白文字列或裁切內容代替間距。
- 以下三處為必要回歸案例：試聽區兩個帶入文字按鈕等寬；底部保存／下一步按鈕間有共同水平淨距；帶入文字操作列與試聽Text之間有共同垂直淨距。修正時先用原生量測證明舊版失敗，再確認修正版通過，並核對整張原尺寸畫面。

1. 正常與縮小視窗 → 比較同列元件實際高度及上下邊界。相同尺寸角色差異須在 2 個 Tk 座標像素內；例外須說明角色與原因。
2. 檢查每個選單、輸入與圖示按鈕 → 確認指示圖示只出現一次，名稱、選取、焦點、停用狀態可辨識。
3. 跑受影響元件的原生回歸測試 → 檢查最終 EXE 的同一操作路徑 → 保留畫面與實測值。測試通過與畫面驗收分開回報。

音訊頁回歸入口：`tests/test_audio_production_ui.py`。新增尺寸／指示符案例時先確認能攔住缺陷版本，再確認修正版通過；避免只斷言樣式名稱。

### 文件列表與檢查接點的兩條基準線

- 標頭帶：量測 `DocumentList.list_header` 與 `AudioJoinWorkspace.header` 的原生上緣、高度，以及「匯入」控制項與頁面標題的垂直中心；每組差值均須≤2個Tk座標像素。
- 內容起點：量測 `DocumentList.batch_view` 與 `AudioJoinWorkspace.main` 的原生上緣，差值須≤2個Tk座標像素。右側框內的接點選單、Text上緣屬於下一層，不是這條基準線。
- 從PDF文稿進入接點頁 → 等待外層延遲布局完成 → 量測兩條線 → 收合及展開文件列表 → 再量測。驗收尺寸與字級沿用根目錄清單；量測前最後一個布局呼叫須經外層正常路徑，讓隱藏文稿工具列覆寫軌道的回歸能被攔住。

這份文件不能取代功能、捲動與資料保存驗收；依本次修改範圍選擇相關檢查，不要求每次重跑全專案。
