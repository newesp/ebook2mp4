# AI 校對時的繁簡與中文標點統一（待評估）

2026-10-26 使用者提出，明確要求「先記著，評估但別實作」。本文件僅記錄需求與可行性，不代表已核定實作、已排入 T08 或變更現行行為。

## 使用者需求

1. AI 校對時，若這份文件大部分是繁體中文，遇到簡體字自動轉成繁體；若大部分是簡體中文，反向統一為簡體。
2. 中文內容中的半形標點，自動轉成全形。

## 可行性評估

兩項皆可實作。建議由程式判定主要字體與執行明確轉換規則，搭配 AI 處理需要語境判斷的疑點，避免只靠提示詞而有時漏轉或過度改寫。可考慮 OpenCC 等詞庫式繁簡轉換工具；尚未選定或安裝任何依賴。

繁簡判斷必須著重能區別字體的字詞，不能把兩者共用漢字都算成某一方。短文、兩種字體比例接近、書內刻意引用另一字體時，需保留不確定狀態或讓使用者指定。簡轉繁有一簡對多繁問題，例如「发」可能對應「發」或「髮」，應依詞語與上下文處理；不承諾零誤判。字體統一與地區用語替換分開，不因轉繁體就擅自把「软件」改寫為「軟體」。

中文語境中的逗號、冒號、分號、問號、驚嘆號、括號等可依規則轉換，例如 `,` → `，`、`()` → `（）`。句點、引號、省略號需另外訂中文標點規則，不能只做 Unicode 字寬替換。英文段落、`3.14`、`U.S.A.`、網址、Email、檔名、程式碼等要辨識並保護，避免改壞內容。

## 建議接入既有校對流程（尚未核定）

- 校對前顯示偵測的主要字體與標點統一設定，允許改為繁體／簡體／保留原樣；判斷不足時不要自行猜測。
- 「文件大部分」可用本機來源全文分析；即使僅校對選取範圍，也只修改與送出所選文字，不為判斷字體額外上傳整份文件。
- 自動轉換納入候選校對稿與差異顯示，再沿用逐段採用／拒絕及撤回；不直接覆寫來源或已確認朗讀稿。此為對「自動」的建議解讀，仍待確認。
- 規則可在本機執行；未使用 AI、匯入來源、PDF 擷取、TTS 前處理是否套用，均不由本次需求自行擴大。
- 保留原版本、選外文字、其他批次及歷史快照；採用修改後須重新確認朗讀稿。

## 後續需確認

- 「這份文件」以來源檔、目前製作批次還是整個書籍專案為判斷單位；同書多份來源可有不同字體。
- 大部分的判斷門檻、最少證據量，以及混用／無法判斷時的處理方式。
- 引用文字是否保留原字體；繁體目標是否需要臺灣／香港字形偏好。
- 中文句點、引號、括號及省略號的具體標點樣式；是否提供各自開關。

現行 Spec v1.1 第 1、8 節明定不自動轉繁簡；未來若核定此需求，須同步調整規格、Gemini 校對規則及行為驗收，不能讓舊規則與新功能互相衝突。目前程式與既有規格均維持原樣。
