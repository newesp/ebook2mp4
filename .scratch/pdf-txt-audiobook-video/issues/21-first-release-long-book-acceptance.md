# T21：代表性長篇完整製作與首版驗收

## Parent

[首版規格 #1](https://github.com/newesp/ebook2mp4/issues/1)

## What to build

用代表性中英文文件從雙入口完成分批製作及總影片，通過長篇規模、朗讀品質與故障恢復的首版驗收，修正阻止通過的問題。

## Acceptance criteria

對應核定 spec User Stories：55、56、57、58、59、60、61、62、63、64、65、75、80、86、87、89、92、94、95。驗收條件：AC-01、AC-02、AC-03、AC-04、AC-05、AC-06、AC-07、AC-08、AC-09、AC-10、AC-11、AC-12、AC-13、AC-14、AC-15、AC-16、AC-17、AC-18、AC-19、AC-20、AC-21、AC-22、AC-23、AC-24、AC-25、AC-26、AC-27、AC-28、AC-29、AC-30、AC-31、AC-32、AC-33、AC-34、AC-35。

- [ ] 在已安裝程式中從 PDF／OCR 及 TXT 各走完整流程，涵蓋 Gemini 候選採用、朗讀確認、分批 MP3／SRT／MP4、總 MP4／SRT，逐項核對父 spec 的 AC-01～AC-35。
- [ ] 至少處理 100 頁範圍、10 萬字元 TXT、30 分鐘成品，記錄硬體、工具版本、實際耗時與記憶體觀察；無整批頁圖／整支影片載入，介面可回應並接受取消。
- [ ] 固定繁中、英文及混合試聽稿涵蓋對話、問句、縮寫、數字與長句；試聽 30～60 秒、5 分鐘及長篇開／中／尾與批次接點，無工具造成漏句、重複、裁尾或累積字幕錯位。
- [ ] 與 novel-generator 用相同文字、同一仍可用音色及語速比較，自然／舒緩與交接停頓可辨，使用者確認最終朗讀節奏預設；分開記錄 OCR、人聲與工具問題。
- [ ] 斷網、Gemini 部分失敗、OCR 單頁失敗、取消、程序中斷、缺檔、不可寫與空間不足的代表情境能恢復並保護舊成品。
- [ ] 真實媒體驗證批次／總時間軸、編碼、字幕與零額外 TTS，記錄客觀測試及人工結果，修正首版阻擋缺陷，不用替身通過宣稱真實服務品質已通過。
- [ ] 本切片的 UI、公開專案工作流程、保存資料及行為測試一併完成；以真實操作及可觀察結果驗證，不以只有內部函式或替身回傳成功代替交付。
